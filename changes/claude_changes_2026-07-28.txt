2026-08-04: scrollable_prints() only captured stdout, not stderr --

Request (yas): "no that made like 1/4 of the bottom scrollabel not the
entire output lol" -- after wrapping the pipeline cell in
scrollable_prints(), most of the output still rendered outside the box.

ROOT CAUSE: scrollable_prints() only did "with
contextlib.redirect_stdout(buf): yield". Warnings (warnings.warn()) and
library logging default to stderr, not stdout -- effectively none of that
was captured. This is a fix to the SHARED function (contrast_response_utils.py),
used by demo 7's load_contrast_section/plot_crf_across_ndfs cells AND
demo 1's pipeline cell -- fixes all of them at once, no per-notebook edit
needed for this part.

FIX:
  Before:
    buf = io.StringIO()
    with contextlib.redirect_stdout(buf):
        yield
  After:
    buf = io.StringIO()
    with contextlib.redirect_stdout(buf), contextlib.redirect_stderr(buf):
        yield

  Docstring updated to explain why (warnings/logging default to stderr)
  and to document the known remaining limitation below.

REMAINING KNOWN LIMITATION (verified via synthetic test, not fixed -- a
real Python gotcha, not a retinanalysis bug): redirect_stdout/
redirect_stderr only reassign sys.stdout/sys.stderr at the Python level.
A library that configures a logging.StreamHandler ONCE, early (e.g. at
import time -- plausible for DataJoint's own connection-banner logging),
captures a REFERENCE to the stream object at construction time and keeps
writing to THAT object regardless of later sys.stdout/sys.stderr
reassignment. Confirmed exactly this failure mode with a synthetic test:
a logging.StreamHandler(sys.stderr) constructed BEFORE entering "with
scrollable_prints():" still writes outside the box, while a plain
print(..., file=sys.stderr) and warnings.warn(...) (both do a live
sys.stderr lookup at call time, not construction time) are now correctly
captured. Fixing the StreamHandler case would need OS-level file-
descriptor redirection (os.dup2), which risks interacting badly with how
Jupyter/ipykernel itself captures stdout/stderr for cell output --not
something safely verifiable without a live kernel, so not attempted.
Flagged to yas rather than guessed at blind.
